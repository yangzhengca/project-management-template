# Projects — Deep Dive

## Project Outcome Discipline

A Project exists to deliver a measurable outcome. If a Project does not have a defined objective, a measurable success metric, a bounded scope, and a timeline — it is not ready to be Active.

Projects represent outcomes, not effort.

## Scope Integrity

Projects must remain tightly aligned to their objective. Warning signs of scope drift:
- Issues being added that don't clearly support the objective
- The success metric becoming unclear
- Timeline repeatedly extending
- The Project becoming a container for "related" work

If scope grows materially: reassess boundaries, split into milestone-based Projects if necessary, do not silently expand the objective.

Scope creep at the Project level distorts portfolio reporting.

## Project Health Expectations

Project health should reflect execution reality, timeline accuracy, and movement on the defined metric.

Green means measurable progress toward the outcome. Not optimism. Not activity. Not busyness.

## Q&A

**Q: When should a Project be closed?**
When the defined objective is achieved, the success metric has been reached, or the strategic priority is intentionally stopped. Do not leave Projects Active indefinitely.

**Q: What if a Project misses its timeline?**
The owner must: reassess scope, reassess metric feasibility, update health status, communicate revised expectations.

**Q: What if a Project's objective changes?**
If the objective materially changes: close the original Project, create a new one with the updated objective. Do not mutate Projects beyond recognition. Historical clarity matters.

**Q: What if a Project has no active Issues?**
A Project without active Issues is not active. It should either move back to Planned or be Completed/Archived. Inactive Active Projects distort reporting.
